Claude Graft 2.1.1 is the first Windows release from the main Claude Graft repository, on the same version line as the Mac app. It brings the two Windows ports together: Tyler's, which this release continues, and James's, whose sign-in routing, Store support and safer project ordering are folded in.

## Upgrading

Download `ClaudeGraftApp-win-Setup.exe` from this release and run it. An install of 2.0.0 from the earlier Windows repository is updated by running the same setup over it; there is no need to uninstall first. From 2.1.1 on, Graft updates itself from this repository.

## New

**Claude from the Microsoft Store.** Graft finds the Store version of Claude Desktop and its profiles where Windows keeps them, as well as the version installed from claude.ai.

**Sign-ins go back where they started.** A Claude sign-in that finishes in the browser returns to the profile that began it, not to the main Claude. Graft offers itself in Windows' own picker for Claude links, under its own name.

**Open a Claude from its sidebar row,** with a sign that it is opening.

**A new Claude starts with chats of its own,** as on the Mac. Reading another Claude's chats is chosen afterwards, in its details.

**A state report after every pass,** as the Mac app writes, beside the diagnostics log: what Graft found and what it did, for a bug report to paste in.

**Donate** in the sidebar and the notification-area menu, with a red heart, opens the tip dialog for the author and the Windows port's maintainer. Settings › About credits the Windows port to Tyler, with parts of James's.

## Fixed

- Settings stays centred inside a wide or maximised window, instead of running past its right edge.
- A new Claude's folder follows its name as it is typed, until the folder is changed by hand.
- The title above a Claude says Running or Not running as soon as its window opens or closes, not only after another Claude is chosen.
- The diagnostics log says what became of a Google or company sign-in Graft was asked to route: which Claude it went to, or why it stopped. The link itself is never written down.
- The diagnostics log no longer records a chat's title when its record is filed.
- A project order write that fails partway is put back on every profile it reached, rather than left half done.
- A pass that cannot get the state lock waits for the next one instead of running unlocked.
- Graft's own data stays in AppData whatever folder the profiles live in.
- A folder reached through several junctions is recognised as inside its profile.
- Pressing Update for Claude Desktop always does something, and shows which version is waiting.
- A development build no longer replaces itself with the release.
- The small icon sizes are drawn on the pixel grid, so they are sharp in the notification area.
